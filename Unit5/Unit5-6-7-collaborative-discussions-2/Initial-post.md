# Initial Post

Agent communication languages (ACLs) such as the Knowledge Query and Manipulation Language (KQML) are valuable because they communicate not only data, but also the intended social action. Austin (1975) established that utterances can perform actions, while Searle (1969) distinguished propositional content from illocutionary force: the same proposition may be asserted, queried or requested. KQML operationalises this distinction through performatives such as `ask-if`, `tell` and `achieve`, while keeping the content language and ontology separate (Finin *et al*., 1993). Therefore, a message can state what an agent intends without prescribing the receiver’s internal implementation.

This separation offers loose coupling, autonomy and interoperability across heterogeneous systems. In a supply-chain system, for example, a purchasing agent could request that a logistics agent achieve a delivery goal without knowing whether the receiver uses Java, Python, a database or a planning model. This is consistent with Wooldridge’s (2009) account of multi-agent systems as societies of autonomous entities whose interactions may be cooperative or self-interested. It also supports the broader AI view of agents as systems that perceive and act to pursue objectives, including situations involving multiple decision-makers (Russell and Norvig, 2021). ACL messages can be asynchronous, routed between distributed agents and organised into conversations, which makes them more suitable than local calls when participants are independently designed or dynamically discovered.

However, syntactic standardisation does not guarantee shared meaning. KQML’s early specification left room for varying performative semantics and did not prescribe one transport mechanism, so two implementations could exchange valid-looking messages yet interpret them differently (Finin *et al*., 1993). Agents must also agree on content languages, ontologies, protocol states and error responses. Payne and Tamma (2014) demonstrate why this is difficult: agents may possess incomplete, asymmetric and private knowledge of ontological correspondences. Their Correspondence Inclusion Dialogue shows that negotiated alignment can approach a centralised solution while limiting disclosure, but decentralisation also makes global consistency harder to verify. ACL infrastructure therefore adds parsing, routing, conversation tracking, validation and security overhead.

Method invocation in Python or Java is simpler. A call such as `inventory.check_stock(item)` identifies a known receiver, operation and argument contract. It is normally faster, easier to test and more predictable because caller and callee share an implementation context. The trade-off is tighter coupling: the caller must know the interface, and the callee has less autonomy to interpret, refuse or negotiate the goal. A remote procedure call can cross a network, but it still presents interaction as invoking a predefined operation rather than performing a communicative act.

Consequently, neither mechanism should replace the other. I would use ordinary methods for deterministic work within an agent, such as validating a product identifier, and ACL messages at boundaries where autonomous agents must express intentions, negotiate meaning or coordinate under uncertainty. This hybrid design gains semantic flexibility only where its additional complexity is justified.
